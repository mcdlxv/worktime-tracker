## Как проверяется код, написанный ИИ

- **TDD.** Тест пишется до реализации и сначала должен упасть.
- **Автоматические проверки.** `npm run check` (ESLint, типы, тесты) и `prettier --check` запускаются и локально, и в CI.
- **API по установленным версиям.** API библиотек сверяется с документацией и типами установленных версий (`node_modules/next/dist/docs`, `.d.ts`), а не с памятью модели: у Next 16, Vitest 5 и zod 4 есть несовместимые изменения.
- **Эксперимент перед кодом.** Допущения проверяются экспериментом, прежде чем попасть в код (см. ошибки № 1 и 2).
- **Ревью человеком.** Человек читает дифф каждого этапа.

## Найденные и исправленные ошибки

### № 1. На Windows файл базы не удаляется после закрытия клиента

- **Где:** тесты на Windows.
- **Симптом:** удаление файла БД после `client.close()` падает с `EBUSY`.
- **Причина:** libSQL держит файл открытым, пока сборщик мусора не уничтожит нативные объекты подготовленных выражений, включая пробный `SELECT 1` внутри `createClient`. Это подтверждено экспериментом: после принудительного `gc()` файл удаляется сразу.
- **Как нашли:** smoke-тесты упали на этапе уборки; ошибку воспроизвели отдельным скриптом вне Vitest.
- **Исправление:** вместо удаления после каждого теста — один временный корень на весь прогон. Он удаляется после завершения воркеров (`tests/global-setup.ts`).
- **Страж:** smoke-тесты; после прогона в `%TEMP%` не остаётся папок.
- **Коммит:** `364aaea`.

### № 2. Лишний PRAGMA для внешних ключей

- **Где:** `openDatabase`.
- **Симптом:** лишний код и неверный комментарий.
- **Причина:** ИИ перенёс на libSQL поведение стандартного SQLite («внешние ключи выключены по умолчанию») и добавил `PRAGMA foreign_keys = ON`.
- **Как нашли:** тест «PRAGMA на параллельных соединениях» прошёл сразу, хотя должен был упасть. Это заставило перепроверить допущение. Оказалось, libSQL включает и соблюдает внешние ключи по умолчанию.
- **Исправление:** `PRAGMA` удалён. Теперь тест проверяет поведение, а не флаг: строка со ссылкой на несуществующего родителя отклоняется.
- **Страж:** тест S3 в `tests/smoke/db.test.ts`.
- **Коммит:** `364aaea`.

### № 3. Ошибка сертификата при установке пакетов

- **Где:** окружение.
- **Симптом:** `npm install` падает с `SELF_SIGNED_CERT_IN_CHAIN`.
- **Причина:** прокси-шлюз сети вскрывал HTTPS. ИИ сначала предположил антивирус и посоветовал добавить его сертификат в доверенные. **Совет был ошибочным** и отозван.
- **Как нашли:** проверка цепочки сертификатов (`openssl s_client`) показала чужой корневой центр.
- **Исправление:** проверку TLS не отключали и чужому сертификату доверие не давали; зависимости поставлены из другой сети.
- **Страж:** нет.
- **Коммит:** нет.
